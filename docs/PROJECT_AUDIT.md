检查日期：2026-10-03。本文件保留修复前的检查基线；用户已授权实施，当前结果见 [实施验收报告](ACCEPTANCE.md)。本地名称按用户最终确认使用“云游南疆”，GitHub 继续使用 yunyou-nanjiang。

## 1. 检查范围与结论

项目使用 Vue 3、Vite 8、Vant 4、ECharts 6，并通过高德地图展示景点。本地已有 Node.js AI 代理、地图与路线工具函数、轮播逻辑和测试，是值得保留的原型基础。

当前最需要补齐的是可信数据、真实路线、部署链路和用户需求验证。文件数量不多，没有必要立刻改造成复杂的多包工程。

GitHub 仓库为 [Hua-bing-666/yunyou-nanjiang](https://github.com/Hua-bing-666/yunyou-nanjiang)，默认分支为 `main`。产品页面与原 README 使用“云游南疆”。仓库名保持 `yunyou-nanjiang`，建议本地外层目录也采用这一名称，避免“南江／南疆”混用。

## 3. 问题清单与验收

P0：对外试点前处理；P1：首个可用版本处理；P2：需求验证后实施。

| 编号／优先级 | 证据与问题 | 对项目的影响 | 处理与验收 |
| --- | --- | --- | --- |
| A01 / P0 | 两个 workflow 会打印云密钥前 10 个字符 | 日志可能暴露部分凭据；不应认为 GitHub 会自动遮蔽截断片段 | 删除片段输出，诊断仅报告是否配置；检查已有日志是否出现片段，按结果处理相关凭据；新日志不含秘密 |
| A02 / P0 | 地图加载器和天气组件内有固定 API Key | 不同服务 Key 配置混在源码，天气 REST Key 在浏览器暴露 | Web 地图 Key 按官方要求限制来源域名并外置配置；天气通过服务端代理；不把服务端秘密写入 `VITE_*` |
| A03 / P0 | AI 代理无请求体上限／限流／上游超时，允许任意 CORS 来源，直接返回异常文本 | 若作为公网服务，会出现资源消耗及错误信息暴露；当前启动脚本只监听回环地址 | 上线前限制体积／字段、超时、速率和费用；收紧来源或同源；400/413/429/502/504 有可理解响应 |
| A04 / P0 | AI 上下文来自浏览器提交的数据，用户可修改 `context` | 无法保证答案依据平台审核资料 | 服务端构建可信上下文；标明来源和更新时间；不确定信息明确说明 |
| A05 / P0 | `routes.js` 手工列出 `routeGeometry`，工具再生成贝塞尔曲线 | 视觉连线无法证明可通行、距离、耗时；固定 3／4 天缺少依据 | 用正规道路规划结果；失败时标注“路线示意”，不伪造车程；试点路线经本地合作人复核 |
| A06 / P0 | 票价、开放时间、文化故事在 `data.js`，无来源／核验日期；部分坐标待核验 | 错误信息会影响真实出行与品牌信任 | 每个公开条目有来源、核验日期、内容负责人；未核验条目不进入推荐／AI 事实回答 |
| A07 / P0 | Login 固定账号，`checkLogin` 只认本地用户名；所有首页内容被登录遮罩拦住 | 不是服务端身份校验，同时增加推广访问阻力 | 开放游客浏览；本地收藏明确保存在当前设备；仅在确需云端保存时建立服务端认证 |
| A08 / P0 | 评论由模板生成并以游客口吻展示，未见样例标识；看板只统计本地条目 | 用户可能误认真实评价或真实经营数据 | 评论标注演示或改为个人笔记；看板标明“本站资料分布”，后续经营指标需真实事件数据 |
| A09 / P0 | workflow 启用 npm 缓存，却未指定子目录锁文件路径；无 `npm test`；缺部署配置时 `exit 0`；尾部指向不存在的 `backend` | CI 存在失败风险、检查缺失、部署成功误报及过时提示 | 设置 `cache-dependency-path`，统一 Node 版本，test 后 build；部署缺配置显示跳过／失败，PR 不部署；干净克隆运行成功 |
| A10 / P1 | 收藏／评论 `JSON.parse` 未捕获损坏数据，写存储也无兜底 | 异常缓存或受限存储环境可能影响初始化和交互 | 对内容结构校验，损坏时恢复空值；写失败反馈；在损坏缓存／禁用存储条件下页面仍可用 |
| A11 / P1 | `toggleLike` 只改内存；发评论延时结束才读取当前景点 ID | 点赞不持久；快速切换景点可能将评论写入其他条目 | 点赞立即保存；发送时捕获景点和文字；切换后不得误写；浏览器复现测试 |
| A12 / P1 | 使用 `pushState`，但初始化未见依据 URL 还原页面；`popstate` 依据当前布尔值依次关闭页面 | 深链接／刷新／前进后退一致性有风险，需浏览器复现 | 用 Vue Router 或统一导航状态；详情直达、刷新、返回、前进和静态站回退全部验收 |
| A13 / P1 | 搜索提示写“景点、路线”，实际只按景点名称筛选且截取前 5 个 | 功能承诺与结果不一致 | 先补全线路、地区／主题搜索，或调整提示；增加无结果引导 |
| A14 / P1 | 地图 SDK 加载失败后残留 script；天气只在 mount 请求 | 地图重试可能等待不再触发的 load；切换景点天气可能过期 | 失败移除 script 并可重试；监听 adcode 变化、取消旧请求；加载／失败状态可见 |
| A15 / P1 | README 称纯前端模拟 AI，实际本地已请求 `/api/chat`；启动脚本只启动前端 | 按文档启动时 AI 不可用；静态部署无 API 转发 | 区分展示模式／真实 AI 模式，明确前后端启动和生产同源反代；未配服务时仍可读景点 |
| A16 / P2 | 主组件承担地图、导航、详情、轮播、收藏、评论；统计地区靠地址字符串判断 | 改一个功能容易影响其他功能，地区数据口径不统一 | 分业务拆组件／composable；结构化地区字段；先保证行为再重构 |

对 A10–A14 的描述基于代码路径，不宣称已经在浏览器中复现全部现象。真实服务配置有效性也尚未验证。

## 6. 执行与同步顺序

1. 把当前已跟踪差异和有用的未跟踪文件保全；配置与密钥保持本地。核对远程 main、本地清理提交和未提交模块的差异。
2. 先提交基础状态和修复，再以独立提交移动文档／脚本；每一步查看 diff，避免混入无关个人文件。
3. 更新根 README、锁文件路径、环境示例和启动说明；在新目录做一次 `npm ci`、测试、构建与启动检查。
4. 本地外层目录改为 `yunyou-nanjiang`：停止该项目进程、退出占用目录的终端，从父目录改名；重新绑定桌面应用工作区并检查绝对路径。
5. 通过 `codex/` 分支同步；代码评审后再合并 main。改名不需要创建新仓库，不强推、不重写远程历史。
6. 生产部署作为独立步骤，核验地图／天气／AI 同源接口、详情页刷新及回滚。GitHub 同步成功不等于网站上线成功。

本轮同步只包含这份检查报告、主规划和文档索引。目录改名、删除和上述修复均未执行。
