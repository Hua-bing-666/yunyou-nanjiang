# 数据库与管理后台

版本：0.2.0。日期：2026-11-07。

## 启动和账号

使用 Node.js 24.5或更新的24 LTS版本，在 `my-travel` 执行：

```powershell
npm ci
npm run dev
```

游客开发网址为 `http://127.0.0.1:5173/`，后台为 `http://127.0.0.1:5173/admin`。生产预览执行 `npm run build` 和 `npm start`，网页、后台与API都由 `http://127.0.0.1:3001/` 提供。

首次启动自动创建SQLite数据库和管理员。没有设置 `ADMIN_PASSWORD` 时，会生成随机密码，写入本机 `my-travel/data/admin-bootstrap.txt`，不会输出到日志或提交到Git。使用该凭证登录，进入“账号设置”修改密码；修改后所有管理员会话失效。密码采用带随机盐的scrypt摘要保存。

可以在首次初始化前通过私有配置设置 `ADMIN_USERNAME`、至少12位的 `ADMIN_PASSWORD`。初始化之后修改这些环境变量不会覆盖已有管理员。

## 后台功能

- 工作概览：当前数据库的内容数、游客自愿资料数、行程数与最近维护记录。
- 目的地：新建、编辑、删除或下架；维护介绍、来源、别名、图片路径和点位状态。仍被路线引用的景点不能直接删除。
- 路线：按日选择景点与顺序，维护提醒、发布状态；首期所有线路继续作为待核验草稿。已有游客保存的路线可下架，不能直接删除。
- 文化资料：维护正文、关键词、来源与原文日期、审核和发布状态。编辑后游客重新读取目录即可获得新版本。
- 游客与行程：按昵称、城市或兴趣查询，查看自愿保存的行程，维护内部备注，删除整份记录，导出当前页CSV。删除游客会级联删除其行程。
- AI导览助手：设置本地／模型模式、模型名称、日额度和服务密钥；连接检查及有来源的资料问答；不自动发布生成内容。
- 账号设置：修改当前密码并注销全部管理会话。

## 数据存储

默认文件为 `my-travel/data/yunyou.sqlite`，可用 `DATABASE_PATH` 指定受保护的绝对路径。SQLite启用WAL、外键和忙等待；迁移表确保初始数据只导入一次，重启不会覆盖后台编辑。

| 表 | 用途 |
| --- | --- |
| `migrations` | 数据结构／种子导入版本 |
| `content` | 目的地、路线、文化短文及修订版本 |
| `admins` / `sessions` | 管理员密码摘要、会话令牌摘要与到期时间 |
| `visitors` | 随机编号、访问凭证摘要、自愿资料、同意时间、内部备注 |
| `itineraries` | 游客主动保存的路线与出发日期；游客外键级联删除 |
| `settings` | AI模式、模型、额度及加密密钥值 |
| `ai_usage` | UTC日界线下的持久化模型请求次数 |
| `audit` | 管理员、操作类型、对象及时间；不记录密码、密钥或完整游客聊天 |

数据库、WAL文件、初始密码、加密主密钥均位于忽略目录，不进入代码或发布包。游客资料没有端到端加密，管理员能够按用途读取；部署负责人需保护数据库与备份目录。

## AI配置和网络

沿用既有DeepSeek兼容接口。服务地址通过服务端 `DEEPSEEK_BASE_URL` 设置；后台可改模型、模式和密钥，不能任意修改外部地址。密钥用AES-256-GCM加密，主密钥独立存放在数据库目录的 `settings.key`。管理GET接口只返回“是否配置”，不会返回密钥。

站内助手与后台问答共用数据库中的已发布审核资料。实时开放、价格、通行等问题继续返回核验提示。日额度写入SQLite，重启或调整模型不能重置已用次数；失败的上游尝试也计入额度。多机分库部署需另建共享预算。

`AI_MODE=local` 可强制本地模式。没有有效密钥时本地资料仍可使用。连接检查只有在模型模式且存在密钥时才发起真实请求，并计入额度。

需要代理的机器可在私有 `.env.local` 设置 `HTTPS_PROXY` 和 `NO_PROXY`。`server/launch.js` 在读取配置后启动启用环境代理的子进程，开发／生产统一入口均使用此启动器。代理地址不作为公共默认值写入代码；本机已配置可用代理并验证真实模型回复。

## API概要

| 路径 | 用途 |
| --- | --- |
| `GET /api/catalog` | 公开目录，支持ETag／304及gzip，不含游客或AI设置 |
| `/api/admin/login`、`session`、`logout`、`password` | 登录、会话查询、注销、改密码 |
| `/api/admin/overview` | 数据库概览和最近维护记录 |
| `/api/admin/spots`、`routes`、`articles`，及其 `/:id` | 管理内容的查询、新建、更新、删除 |
| `/api/admin/visitors`、`/:id` | 游客查询、维护备注、删除 |
| `/api/admin/ai`、`ai/test`、`ai/query` | AI设置、连接检查及资料问答 |
| `/api/visitor` | 当前游客读取、自愿提交／更新、删除自己资料 |
| `/api/visitor/itineraries`、`/:id` | 当前游客保存和删除自己的服务端行程 |

管理会话为8小时HttpOnly Cookie，SameSite=Strict；游客凭证Cookie为30天。生产HTTPS反代设置 `COOKIE_SECURE=1`。来源校验、请求体上限和每IP限流沿用并覆盖新接口。管理员编辑最大64 KiB，普通JSON请求最大16 KiB。

## 备份、恢复与发布

执行 `npm run db:backup`，使用SQLite在线备份API，将数据库与 `settings.key` 放入同目录下的 `backups/时间戳/`；不要在服务运行时直接复制主SQLite文件而忽略WAL。

恢复时停止服务，先保留当前数据库目录的副本，再从同一份备份恢复数据库与加密主密钥；启动后检查健康、目录、管理员登录与AI设置。丢失 `settings.key` 无法解密已保存的模型密钥。初始密码文件不是数据库恢复所必需。

发布包新增了服务端共用的 `src/utils/mapAvailability.js`，整个 `server` 目录包含数据库、迁移、数据种子和启动器。部署需保留可写且持久化的数据目录，不能只发布 `dist`。镜像替换或容器重建时应挂载该目录。
