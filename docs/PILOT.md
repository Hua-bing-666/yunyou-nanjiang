# 云游南疆：创业试点执行包

本轮完成网站技术整理，同时把六周规划转成可记录的试点任务。以下是待执行表格和判断方法，**没有虚构游客访谈、合作方、流量或收入**。项目值得作为低成本、局部文化导览试点；是否成为创业业务，要由重复需求、合作意愿和维护成本证明。

2026-10-04 用户确认暂时没有当地资源，先做公开资料与线上样品。当前执行顺序以 [线上样品规划](ONLINE_SAMPLE.md) 为准；以下合作投放与实地任务保留为后续条件，不计为已经完成。

## 起步范围

先从喀什古城的手工艺文化导览选择一个街区、5–8 个点位、1–2 条短线。这个方向来自现有资料基础，并非已验证市场结论。暂不扩张为全南疆预订平台。优先寻找一位当地内容维护者和两家愿意共同试用的手工艺／文旅合作方。

所需痛点证据：游客是否找不到文化体验入口；线上介绍与现场开放是否不一致；是否只保存图片却难形成可执行安排；合作方是否愿意为内容维护或导览交付付费。政策方向与 GitHub 案例只帮助提出假设，不能代替这些证据。

## 游客访谈记录模板

以近期实际出游者为对象，先进行约 10 次半结构访谈（样本目标，不是统计代表性证明）。征得同意后只记录必要信息。

| 字段 | 填写要求 |
| --- | --- |
| 记录编号／日期 | 匿名编号，不写身份证、住址或不必要联系方式 |
| 最近一次相关出游 | 地点、同行人数、准备方式、具体日期范围 |
| 上一次卡住的任务 | 当时要完成什么？在哪里找？怎么解决？ |
| 实际代价 | 额外花费时间、错过体验、信息错误；区分事实与感受 |
| 现有替代 | 高德、携程、小红书、导游等各解决了什么 |
| 现场任务 | 用网站找到一个体验、查看依据、保存或下载行程 |
| 观察 | 是否独立完成、阻断位置、是否需要解释，不替用户操作 |
| 再使用意愿 | 在什么具体场景会再用？为什么？不直接诱导“喜不喜欢” |

## 合作方访谈与交付模板

| 字段 | 填写要求 |
| --- | --- |
| 合作对象 | 类型、公开名称、访谈同意范围；未经允许不公开个人联系方式 |
| 当前获客／内容渠道 | 现有维护方式、实际问题和投入 |
| 可提供资料 | 官方地址、入口坐标、营业安排、图片授权、文化介绍负责人 |
| 可试用位置 | 现场二维码、公众号入口等；需要明确许可，不自动投放 |
| 可承诺交付 | 一份经审核的导览页、路线或内容维护，写明验收责任 |
| 商业反馈 | 对具体交付与报价的反应，记录拒绝原因；意向不是收入 |
| 维护成本 | 每次核验、纠错、更新、回访的工时和外部费用 |

## 任务与决策

| 阶段 | 待完成动作 | 证据与进入条件 |
| --- | --- | --- |
| 需求验证 | 访谈约 10 位游客与至少 2 家候选合作方 | 重复问题、具体替代与使用场景；不以泛泛好评通过 |
| 内容审核 | 5–8 个点位逐条核验来源、入口、授权与维护者 | 所有试点内容通过；当前 12 个参考点位不能直接算入 |
| 路线审核 | 实际走通 1–2 条小范围路线 | 时间、交通、开放依赖与替代方案有记录 |
| 小规模试用 | 经合作方许可投放入口，观察目标用户完成任务 | 记录真实成功／失败与维护工时，不编造 KPI |
| 商业复盘 | 提出具体服务与报价，再次访谈合作方 | 实际采购进展与成本支持继续；无需求则收缩／调整 |

事件表可先人工记录 `匿名会话 / 日期 / 入口 / 任务 / 是否完成 / 保存或下载 / 错误 / 是否回访`。次数不等于用户数；同一用户多次点击需说明去重口径。没有必要先装全量追踪系统。

主规划中的任务完成率、合作意向、继续／停止阈值均为项目内部试验标准，不能描述为行业平均水平。若没有可靠内容维护者、反复出现出行信息错误，或合作方只愿免费展示，先暂停商业扩张、调整交付形式。
