# 部署、健康检查与回滚

推荐先使用 Node 同源托管网页和 API。当前没有建立或发布新的公网站点；GitHub 同步不等于已上线。内容、地图安全代理、域名与实际运行配置核验后再开展试点。

## 同源生产运行

在服务器的项目目录执行：

```sh
cd my-travel
npm ci
npm test
npm run build
npm start
```

构建前设置公开的 `VITE_AMAP_KEY` 和 `VITE_AMAP_SERVICE_HOST`。运行时通过受保护的 `.env.local` 或服务环境注入服务端 Key。`npm start` 将 `dist/` 与 `/api/*` 托管在同一服务，默认 `127.0.0.1:3001`；支持 `/detail/1`、`/routes?route=1` 等路径刷新。只部署 `dist/` 不会获得天气／道路／AI API。

使用进程管理器或系统服务保证崩溃重启，设置 HTTPS 反向代理。最低代理示例（证书、域名按实际环境填写）：

```nginx
location / {
    proxy_pass http://127.0.0.1:3001;
    proxy_set_header Host $host;
    proxy_http_version 1.1;
    proxy_read_timeout 35s;
    client_max_body_size 16k;
}
```

地图的 `/_AMapService` 安全代理需另按高德文档配置，不能让这个通用 location 代替。站点 HTTPS、代理、安全密钥与允许域名均需实测。

服务端限制 JSON 16 KiB、问题 1200 字、历史 8 条、来源白名单、每个连接 IP 每分钟 30 次 API 请求和模型每日预算。**这是小规模单进程保护**：反向代理默认让访客共用代理 IP 配额，服务重启重置日预算，多副本也各自计算。正式推广前需在入口实现真实客户端限流与共享预算；不能直接信任访客自带的 `X-Forwarded-For`。必须在提供商控制台设置消费上限，现有代码上限不等于财务保障。

## 发布验证

| 检查 | 合格条件 |
| --- | --- |
| `/api/health` | HTTP 200，`{"status":"ok"}`；仅证明进程存活，不证明外部服务可用 |
| 首页与 `/detail/1` 刷新 | HTTP 200，图片与样式正常 |
| `/api/weather?adcode=653101` | 配置有效时返回天气与报告时间；缺配置清楚提示 |
| `/api/route?id=1` | 返回提供商道路几何及查询时间，点位待核验标识仍保留 |
| 助手 | 指定资料问题返回来源；本地模式／限流／异常提示准确 |
| 外部故障 | 不影响浏览、本地保存与已下载文本；失败可重试 |
| 私有文件 | `/.env`、反斜线路径、缺失 JS 404，服务端秘密不进产物或日志 |

首次发布用少量访问和自有设备验收，记录提交号、URL、环境、配置存在性、健康结果和回滚版本，不记录秘密。

## GitHub 工作流

`ci.yml` 在 main、codex 分支与 PR 运行干净安装、格式、依赖审计、单元、构建和 Chrome／Firefox／手机模拟验收，不需要秘密。

`release-package.yml` 仅手动产生可审查发布包，读取仓库 Variables 中公开的地图配置；**不执行云端发布，也不宣称部署成功**。旧自动 CloudBase 部署和密钥片段诊断已移除，避免缺少配置却显示成功。

保留 `webify.config.json` 作为历史静态托管入口；如果继续使用，需明确配置 `/api` 后端转发和 SPA 回退后再验收。当前没有在该渠道验证生产链路。

## 回滚

每次部署保存上一版本的代码提交、锁文件和构建包。新版本检查失败时，切回上一已验证版本、`npm ci`、恢复该版本构建包并重启进程，再检查健康与详情刷新。秘密留在服务环境，不随版本回滚或进入发布包。用户本地数据目前无服务器迁移；若改变其格式，保持旧格式兼容或说明迁移。
