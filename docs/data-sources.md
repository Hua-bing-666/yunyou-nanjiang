## 数据维护字段

`spots.js` 提供 `sources / reviewedAt / status / maintainer / imageLicense / coordinateStatus / coordinateSource`，以及搜索 `aliases`、具体 `coordinateNote / visitNote`。目前负责人统一待指定，不虚构内容团队。`source-reviewed` 介绍可以进入助手资料；`draft` 内容不进入文化事实上下文。实时门票、开放、通行等问题在服务端直接进入本地核验提示，不调用模型猜测。地图支持 `reference / suspended / verified`；本轮没有 `verified` 入口。

正式试点每条公开点位需填写：

| 字段 | 验收证据 |
| --- | --- |
| 来源／核验日期／负责人 | 原文链接或授权提供资料，明确谁维护与何时回看 |
| 名称／入口坐标／坐标系 | 当地负责人确认，现场或正规地图核对入口；高德使用 GCJ-02，不能直接混用未转换点位 |
| 开放／票价／预约 | 对应日期的官方公告；变化频繁时设复核周期，不确定则不给数值 |
| 图片／文字 | 作者、来源、许可范围与证明文件；可公开访问不代表可商用 |
| 体验与联系人 | 实际可提供的体验、许可与对外联系范围，不泄露私人信息 |
| 路线 | 逐段交通、现场耗时、预约依赖、替代方案与核验者 |

道路接口只能证明提供商返回了基于给定坐标的道路结果，不能证明坐标正确、边境通行获准、预约成功或每天行程合理。

## 纠错流程

页面提供 GitHub Issue 反馈入口。收到问题后记录 `编号 / 条目 / 事实与证据 / 负责人 / 暂停或修正 / 核验日期 / 提交号`。关键出行错误先撤下相应内容，再验证并发布修正；一般文化文字纠错保留来源与变更记录。

当前没有自动向合作方发消息或自动发布未经审核的投稿。正式内容复核流程与用户访谈模板见 [创业试点执行包](PILOT.md)。
